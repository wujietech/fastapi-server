## 👥 团队角色与职责

### 🌟 naiyue (王廼悦) - 项目负责人
- **核心职责**: 项目总体把控、产品设计决策、质量标准制定
- **日常工作**: 文档评审、技术方案确认、进度管理、风险控制
- **决策权限**: 最终技术方案决策、优先级调整、资源分配
- **沟通频率**: 每日站会、关键节点实时沟通

### 🔍 Neo - 技术架构师 & 文档评审专家
- **核心职责**: 架构设计、文档深度评审、技术方案优化
- **专业能力**: 系统架构设计、技术选型、性能优化、安全设计
- **评审标准**: 六维度质量评估、技术可行性分析、风险识别
- **输出要求**: 批判性评审报告、优化建议、风险预警

### 🤖 Alex (Cursor AI) - 技术开发伙伴
- **核心职责**: 代码生成、技术实现、开发效率提升
- **能力特点**: 快速编码、模式识别、代码优化、文档理解
- **协作模式**: 基于设计文档进行精准代码生成
- **质量保障**: 代码规范遵循、最佳实践应用

## 🔄 协作流程规范

### 📝 文档评审流程

#### Phase 1: 文档提交与初审
1. **Neo文档创建** → **naiyue初审** → **技术可行性确认**
2. **评审周期**: 24-48小时内完成初审反馈
3. **评审标准**: 技术准确性、实现可行性、文档完整性

#### Phase 2: 深度评审与优化
1. **Neo批判性分析** → **naiyue确认修改** → **文档定稿**
2. **评审维度**: 六维度质量标准全面检查
3. **输出标准**: 可直接用于代码生成的技术规范

#### Phase 3: 开发就绪确认
1. **文档定稿** → **Alex技术验证** → **开发启动**
2. **验证内容**: API设计合理性、数据模型完整性、实现细节明确性

### 💻 代码开发流程

#### 开发启动条件
- ✅ 模块设计文档已通过Neo评审
- ✅ naiyue已确认技术方案
- ✅ 开发环境准备就绪
- ✅ 依赖模块接口已明确

#### 开发执行流程
1. **Alex基于文档生成代码** → **本地测试验证** → **Git提交**
2. **naiyue代码审查** → **功能验证** → **集成测试**
3. **Neo架构审查** → **性能评估** → **安全检查**

#### 质量保障机制
- **单元测试覆盖率**: ≥ 90%
- **代码评审频率**: 每日提交必审
- **集成测试**: 每个模块完成后执行
- **性能测试**: 关键路径必须验证

### 🚨 问题处理与改进机制

#### 改进熔断机制
**3次未达目标即讨论原则**:
1. **第1次**: 技术问题 → 内部快速调整
2. **第2次**: 方案问题 → 三方技术讨论
3. **第3次**: 架构问题 → 暂停开发，重新设计

#### 风险升级机制
- **技术风险**: Alex识别 → naiyue评估 → Neo方案建议
- **进度风险**: naiyue监控 → 三方讨论 → 优先级调整
- **质量风险**: Neo评估 → 质量标准重申 → 流程优化

## 📊 沟通协作机制

### 🕐 定期沟通节奏

#### 每日站会 (15分钟)
- **时间**: 每日上午9:00-9:15
- **参与者**: naiyue + Alex
- **内容**: 昨日进展、今日计划、阻塞问题
- **输出**: 当日工作重点、风险识别

#### 双日技术评审 (30-60分钟)
- **时间**: 每两日下午3:00-4:00
- **参与者**: naiyue + Neo + Alex
- **内容**: 技术方案评审、架构优化、质量检查
- **输出**: 技术决策、优化方案、下步计划

#### 周度总结会议 (60分钟)
- **时间**: 每周五下午4:00-5:00
- **参与者**: 全体团队
- **内容**: 周度进展回顾、里程碑评估、风险预警
- **输出**: 周报、下周计划、资源调整

### 💬 即时沟通规范

#### 紧急问题处理
- **P0级**: 阻塞开发进度 → 立即响应 (< 30分钟)
- **P1级**: 影响交付质量 → 4小时内响应
- **P2级**: 一般技术问题 → 当日内响应

#### 沟通渠道优先级
1. **实时对话**: 紧急技术问题、关键决策
2. **项目群组**: 日常进展、文档分享
3. **邮件总结**: 重要决策记录、周度总结
